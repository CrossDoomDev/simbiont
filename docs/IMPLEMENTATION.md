# Реализация GDD в Godot

Основание: предоставленный дизайн-документ «Симбионт — подробный GDD прототипа Playgama», извлечённый текст `gdd_text.txt` и изображения в `references/`. При расхождении документа и прямого запроса пользователя используется **Godot**: HTML/CSS/JavaScript из технической главы GDD заменены на Godot 4.7.1. Web — экспорт Godot, а вся игровая логика написана на GDScript.

## Соответствие систем

| Требование | Реализация |
|---|---|
| Строго top-down 2D | `Node2D`, ортогональное поле, `Camera2D`, четыре направления спрайтов |
| Встроенный тайлмап | `TileMapLayer`, `TileSetAtlasSource`, коллизионный слой TileSet; корабль и миссия |
| Встроенные анимации | `AnimatedSprite2D` / `SpriteFrames` у актёров, `AnimationPlayer` у органов, Tween у попаданий и затемнений |
| Неотделимый симбионт | Один управляемый актёр `HostAndSymbiont`; органическое оружие на руке, контакт отростком |
| Живой корабль | Пять органических точек контакта, пульсация тканей и изменение свечения по стадиям; окна являются HUD |
| Навигация и вылазки | Контакт с навигационным органом → карта → выбор миссии → затемнение; возвращение через меню |
| Бой | Снаряды, автоогонь и ручной прицел, три рядовых типа противников, страж, волны и добыча |
| Общая экономика | Четыре ресурса для корабля и симбионта; покупки, пределы уровней и цены в `scripts/data.gd` |
| Постоянное развитие | Четыре направления симбионта по три уровня; четыре корабельных модуля по четыре стадии |
| Мутации | Шесть вариантов; три предложения за нестабильные фрагменты; сброс между вылазками |
| Сохранение | Версия 1, числовые границы, атомарная замена через `.tmp`, `.bak`, защита от повторного зачисления `run_id` |
| Звук | Собственный процедурный синтез; приглушённый корабельный трек, боевой пульс, отдельные SFX и низкий резонанс без речи |
| Материалы референсов | Исходные изображения GDD отдельно от игровых атласов и отдельно от скриншотов viewport |

Основные файлы: `scripts/main.gd` — цикл игры; `world.gd` — сцены, карта и органы; `actor.gd`, `projectile.gd`, `nest.gd`, `loot.gd` — бой; `ui.gd` и `touch.gd` — интерфейс и ввод; `progress.gd` — профиль и транзакции; `data.gd` — баланс; `audio.gd` — микшер и воспроизведение.

## Принятые решения

**Цель первой миссии — три гнездовых узла.** Страж появляется по ходу вылазки, даёт органическое ядро, но не блокирует возвращение после уничтожения всех узлов. Игрок сам решает, остаться ли ради добычи. Во второй миссии победа над стражем обязательна вместе с тремя узлами.

**После смерти зачисляется 50% ресурсов текущей вылазки**, каждый тип округляется вниз. Прежний склад и постоянные улучшения сохраняются. При успешном возвращении зачисляется 100%. Функция `Progress.deposit_run()` выполняет начисление один раз для уникального идентификатора; повторная обработка не должна дублировать добычу.

**Вторая локация включена в прототип** как «Багровая низина» со споровым оттенком, более сильными противниками и обязательным стражем. Она открывается на II стадии сердца. Это компактный второй вариант арены, а не отдельный открытый мир.

**Автоогонь включён по умолчанию**, ручное направление и огонь доступны мышью или правым стиком. Отображение сенсорных стиков можно менять в настройках. Носитель на корабле остаётся тем же персонажем с органической бронёй; отдельного существа в капсуле нет.

**Баланс оставлен доступным для правки в исходниках.** `GameData.DEATH_KEEP_RATIO`, словари `MISSIONS`, `ENEMIES`, `UPGRADES`, `MODULES`, `MUTATIONS` и `GameData.stats()` задают ресурсные правила, цены, характеристики и доступ. Это конфигурация GDScript, а не внешний JSON и не игровое меню редактора. Геометрия и позиции органов находятся в `world.gd`; число узлов принято равным трём и при его изменении нужно согласовать генерацию, проверку цели и текст UI.

## Пакеты и ограничения прототипа

`export_presets.cfg` содержит native Windows x86_64 release со встроенным PCK и Web без потоков/GDExtension. Применяется проектный GL Compatibility. Web/PWA cross-origin isolation headers отключены; PWA не включён. Описание флагов: [официальная документация Windows exporter](https://docs.godotengine.org/en/stable/classes/class_editorexportplatformwindows.html), [Web exporter](https://docs.godotengine.org/en/stable/classes/class_editorexportplatformweb.html).

Из экспорта исключены `docs/*`, `tools/*`, `tests/*`, `artifacts/*`, `assets/source/*`, `assets/art/*preview*`, `assets/art/contact_sheet.png` и предыдущие сборки в `build/*`. Они остаются в проекте для редактирования и проверки происхождения материалов.

**Playgama SDK пока не подключён.** Проект не заявляет интеграцию рекламы, платформенных сохранений, аналитики, авторизации или публикацию на площадке. Игра работает с локальным профилем. Подключение SDK и проверка событий площадки — отдельный этап перед публикацией.

Сценарии проверок и команды экспорта приведены в `README.md`. Документ описывает реализацию и принятые решения; результаты конкретных прогонов нужно подтверждать журналами и скриншотами, а не наличием команды или тестового сценария.
