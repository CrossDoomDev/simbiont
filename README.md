# Симбионт

Репозиторий: [CrossDoomDev/simbiont](https://github.com/CrossDoomDev/simbiont). Последние запросы пользователя и новый эскиз корабля: [следующая итерация](docs/NEXT_ITERATION.md).

Играбельный прототип 2D экшена на **Godot 4.7.1**, с видом строго сверху. Человек-носитель и симбионт восстанавливают живой корабль за ресурсы, добытые на чужой планете. Проект использует рендерер **GL Compatibility**, встроенные `TileMapLayer` / `TileSet`, `AnimatedSprite2D` / `SpriteFrames` и `AnimationPlayer`.

Это стадия прототипа: баланс, удобство управления и визуальную близость к GDD ещё можно дорабатывать. **Playgama SDK не интегрирован**: рекламы, авторизации, облачных сохранений и отправки событий нет. Windows-версия работает локально без внешних сервисов; Web-версия запускается с локального HTTP-сервера либо веб-хостинга.

## Разработка в облаке

В репозитории находятся исходники Godot, редактируемые сцены, ассеты с исходными изображениями, музыка, дизайн-документ, референсы, тесты и кадры игры. Кеш редактора и готовые сборки пересоздаются и в Git не включаются.

```bash
git clone https://github.com/CrossDoomDev/simbiont.git
cd simbiont
bash tools/setup_cloud.sh
export PATH="$HOME/.local/bin:$PATH"
python3 -m venv .venv
source .venv/bin/activate
python3 -m pip install -r tools/requirements.txt
bash tools/check_cloud.sh
```

Нужны Linux x86_64, Python 3, curl и доступ к официальному GitHub-релизу Godot 4.7.1. Можно использовать уже установленный движок, задав `GODOT_BIN=/path/to/godot`. GitHub Actions запускает импорт, компиляцию всех скриптов, проверки прогресса, геймплея, корабля, боя, звука и запуска, а также валидацию атласов и анатомии персонажа при push/PR. Это проверка проекта, а не автоматическая публикация игры.

Чтобы запустить локальный редактор после клонирования, откройте `project.godot`. Обновления проекта публикуются в единственную ветку `main`. Сохранения игроков, `.env`, `.godot/`, сборки и журналы не должны попадать в коммиты.

## Получение обновлений на Windows

Закройте запущенную игру. В PowerShell из папки проекта выполните:

```powershell
git status
git pull --ff-only origin main
git log -1 --oneline
```

Если есть локальные правки, сохраните их перед обновлением; при ошибке Git не сбрасывайте их принудительно. Откройте `project.godot` из этой же папки в Godot 4.7.1, дождитесь импорта и нажмите **F5**. Это запускает обновлённые исходники. Fetch только получает сведения о коммитах; для обновления файлов нужен Pull.

`git pull` не пересобирает существующий `build/Symbiont.exe`: `Play.cmd` при его наличии запускает именно эту сборку. Для проверки обновления используйте F5 в редакторе или заново экспортируйте Windows-сборку.

## Запуск

Дважды щёлкните **`Play.cmd`**. При наличии `build/Symbiont.exe` запускается готовая сборка; иначе — проект через установленный Godot. **`Open Editor.cmd`** открывает исходный проект в редакторе со сценой живого корабля.

Поиск движка учитывает `GODOT_EXE`, папку `Godot` на рабочем столе, соседнюю `tools/godot-4.7.1` и системный `PATH`. При переносе проекта можно задать путь явно:

```powershell
$env:GODOT_EXE = 'C:\Path\To\Godot_v4.7.1-stable_win64.exe'
.\Play.cmd
```

Для просмотра Web-сборки после экспорта:

```powershell
python -m http.server 8080 --directory build/web --bind 127.0.0.1
```

Откройте `http://127.0.0.1:8080/`. В браузере звук может начаться после первого нажатия. Для запуска Web-версии нужен браузер с WebGL 2.

## Что реализовано

- Живой корабль с сердечным залом, четырьмя отдельными камерами и извилистыми сосудистыми коридорами. Пять органов отвечают за навигацию, развитие симбионта, сердце, восстановление и биохранилище. Проходы и стенки используют нативные коллизии; карта показывает настоящую планировку. Интерфейсы появляются как HUD при контакте; носитель остаётся вместе с симбионтом.
- Лесная вылазка «Шёпот под кронами»: три гнездовых узла, волны ползунов, панцирников и излучателей, мини-босс страж.
- Открываемая «Багровая низина» после второй стадии сердца: из каждого из трёх узлов выходит собственный страж. Для возвращения нужно разрушить все узлы и победить всех троих; HUD показывает общий прогресс.
- Биоимпульсное оружие, ручное наведение, переключаемый автоогонь, попадания, коллизии, здоровье, регенерация, добыча и рост опасности.
- Страж чередует предупреждённый рывок, веерные залпы и удар по площади. При половине здоровья ускоряется; направление и дальность уже объявленной атаки остаются фиксированными, после атаки есть окно восстановления.
- Регенерация начинается через пять секунд без урона. Постоянное улучшение даёт 0,05 HP/с за уровень, модуль — 0,025 HP/с за стадию; максимальная сумма постоянных улучшений — 0,25 HP/с.
- Четыре общих ресурса: биомасса, плотная ткань, энергофермент и органическое ядро. Их можно потратить на четыре направления постоянного развития симбионта или четыре стадии корабельных модулей.
- Все улучшения покупаются только на корабле за ресурсы. Временного выбора из трёх усилений в вылазке нет.
- Дальность биоимпульса — около 344 пикселей от дула (вдвое меньше прежней). Волны растут с 3 до 10 врагов и ускоряются с 1,9 до 0,65 секунды; обычные волны оставляют места для стаи из опухолей.
- В лесу простые опухоли выпускают стаи, вторая уничтоженная — одного стража. В Багровой низине каждая опухоль выпускает босса. Страж быстрее преследует носителя, совершает рывки и выпускает частые веерные залпы.
- Обычные волны выходят из каменных пещер по краям обеих карт: по три входа на каждой стене. Враг выходит из темноты по свободному проходу, затем начинает преследование. Произвольных точек появления возле игрока больше нет; стаи из опухолей и босс сохраняют свой источник.
- Органический интерфейс: сгенерированные хитиновые панели, кнопки, живой фон главного меню, сосудистая карта и единая тема HUD, улучшений, настроек и сенсорных стиков. Девять растягиваемых частей сохраняют углы рамок. Окно от 640×360: HUD привязан к краям, карточки перестраиваются, длинные меню прокручиваются, заголовок и закрытие остаются на месте. При смене размеров удерживаемый сенсорный жест сбрасывается.
- Шрифты с кириллицей: Russo One для заголовков, Exo 2 для текста и кнопок. Буквы увеличены на 2–3 пикселя; игровые значки используют встроенный резерв DejaVu Sans. [Источники и лицензии](assets/fonts/README.md).
- Возврат после цели через меню с затемнением и однократным зачислением добычи. После смерти сохраняется половина каждого ресурса вылазки с округлением вниз; прежний склад не теряется.
- Локальный профиль, резервная копия, проверка полей сохранения, история вылазок, настройки музыки/эффектов/управления и сброс с подтверждением.
- Три оригинальные музыкальные петли: корабельная тема, боевой трек миссии и отдельная ускоренная тема стража; корабельный эмбиент и короткие игровые звуки собственного синтеза. В настройках показана громкость в процентах; ноль отключает музыку.

## Управление

| Действие | ПК | Сенсорный экран |
|---|---|---|
| Движение | WASD или стрелки | Левый стик |
| Прицеливание и огонь | Мышь и удержание ЛКМ | Правый стик |
| Контакт с органом | E рядом с органом | Кнопка контакта |
| Меню / пауза | Esc или кнопка «Меню» | Кнопка «Меню» |
| Завершение вылазки | Esc → «Завершить миссию» после цели | Меню → «Завершить миссию» |

Автоогонь включён по умолчанию и отключается в настройках. Там же можно включить отображение сенсорных стиков. В первой миссии для возвращения достаточно уничтожить три узла; страж даёт дополнительную добычу. Во второй миссии страж входит в обязательную цель.

## Сохранения и материалы

Основной профиль: `user://symbiont_save.json`, резервная копия: `symbiont_save.json.bak`. На Windows стандартная папка Godot — `%APPDATA%\Godot\app_userdata\Симбионт`. Текущая незавершённая вылазка не сохраняется.

Извлечённые изображения GDD находятся в `docs/references/`, их список — `docs/references/index.json`; извлечённый текст — `docs/gdd_text.txt`. Подготовленные игровые атласы находятся в `assets/art/`, исходные сгенерированные изображения — в `assets/source/`. Решения по неоднозначностям документа описаны в [docs/IMPLEMENTATION.md](docs/IMPLEMENTATION.md).

Новые растровые ассеты созданы встроенным `imagegen` по иллюстрациям PDF; точные запросы, источники и сетки находятся в `assets/art/manifest.json`. Тайлсет собирается `tools/build_tile_art.py`. Шрифт Manrope распространяется по SIL OFL; лицензия сохранена в `assets/fonts/OFL.txt`.

Тканевые стены корабля используют отдельный атлас `assets/art/ship_tissue.png`: шесть типов рёбер, корней и органических узлов. Исходник и запрос сохранены в `assets/source/ship-tissue-generated.png` и `assets/art/ship_tissue_manifest.json`; воспроизводимая сборка — `python tools/build_ship_tissue_art.py`. Общую геометрию пола, коллизий и тканевых границ задаёт `scripts/ship_layout.gd`. После изменений только корабля можно запечь его отдельно: `godot --headless --path . --script res://tools/bake_scenes.gd -- --ship-only`.

Редактируемые сцены: `scenes/hub.tscn`, `scenes/forest.tscn`, `scenes/swamp.tscn`. Шесть наборов анимаций — `assets/animations/*.tres`. Их можно пересоздать после изменения генератора мира: `godot --headless --path . --script tools/bake_scenes.gd`.

Скриншоты реального Godot viewport сохраняются в **`artifacts/screenshots/`**: главное меню, корабль, карта, улучшения, бой в лесу, пауза миссии, выполненная цель и результаты миссии. Они создаются командой `--capture` ниже; исходные референсы хранятся отдельно.

## Генерация звука

`tools/generate_audio.py` использует только стандартную библиотеку Python: аддитивный и FM-синтез, фильтрованный шум и пространственные отражения. Внешних музыкальных записей, сэмплов и речи нет. Результат — 21 WAV, 44,1 кГц, stereo PCM16; `hub.wav` — 72 секунды, `mission.wav` — 48 секунд / 120 BPM, `boss_music.wav` — 40 секунд / 144 BPM, `ambient.wav` — 18 секунд. Генерация детерминирована.

```powershell
python tools/generate_audio.py
# Быстро пересобрать только короткие звуки, сохранив длинные треки:
python tools/generate_audio.py --effects-only
```

Параметры, SHA256 и результаты проверки WAV записываются в `assets/audio/manifest.json`. Громкость и смену контекста обслуживает `scripts/audio.gd`.

## Проверки разработчика

Команды выполняются из корня проекта. Они запускают проверки; сам этот список не является отчётом об их успешном прохождении.

```powershell
$godot = powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\tools\launch.ps1 -Mode FindGodot
& $godot --headless --path . --import
& $godot --headless --path . --script res://tests/check_scripts.gd
& $godot --headless --path . --script res://tests/test_progress.gd
& $godot --headless --path . --script res://tests/test_gameplay.gd
& $godot --headless --path . --script res://tests/test_touch.gd
& $godot --headless --path . --script res://tests/test_ship.gd
& $godot --headless --path . --script res://tests/test_combat.gd
& $godot --headless --path . --script res://tests/test_caves.gd
& $godot --headless --path . --script res://tests/test_fonts.gd
& $godot --headless --path . --script res://tests/test_ui_layout.gd
& $godot --headless --path . --script res://tests/test_audio.gd -- --audio-test
& $godot --headless --path . -- --runtime-test
# Для скриншотов требуется настоящий графический viewport:
& $godot --path . -- --capture
```

Проверки и `--capture` используют отдельные тестовые профили. Обычный `symbiont_save.json` не изменяется. Проверяйте код возврата и сообщения `SCRIPT_CHECKS`, `FONT_TESTS`, `PROGRESS_TESTS`, `GAMEPLAY_TESTS`, `TOUCH_TESTS`, `SHIP_TESTS`, `COMBAT_TESTS`, `CAVE_TESTS`, `UI_LAYOUT_TESTS`, `AUDIO_TESTS`, `RUNTIME_TESTS`, `SCREENSHOTS_OK`, а также ошибки в журнале. Звуковой тест захватывает фактический PCM через `AudioServer`; флаг `--record-audio` после `--audio-test` сохраняет записи в `artifacts/audio/`.

Исходник пещеры и запрос генерации сохранены в `assets/source/cave-entrance-generated.png` и `assets/art/cave_manifest.json`. Сборка изображения: `python tools/build_cave_art.py`; пересборка только двух карт с редактируемыми входами и маркерами выхода: `godot --headless --path . --script res://tools/bake_scenes.gd -- --missions-only`. Снимки четырёх сторон: `godot --path . --audio-driver Dummy --script res://tools/capture_caves.gd` при наличии графического контекста.

Исходники интерфейса — `assets/source/ui-*-generated.png`, точные запросы и границы девяти частей — `assets/art/ui/manifest.json`. Сборка: `python tools/build_ui_art.py`. Тема Godot — `scripts/ui_skin.gd`. Реальные снимки меню, карты, HUD, портретного и короткого окна и трёх стражей воспроизводит `godot --path . --audio-driver Dummy --script res://tools/capture_symbiote_ui.gd`. Разметка проверяется изменением настоящего Window, а не масштабированием готового скриншота.

Новые кадры помещений, предупреждений атак и четырёх направлений ходьбы можно воспроизвести командой `godot --path . --script res://tools/capture_iteration.gd` при наличии графического контекста. Она сохраняет `11_`–`16_` в `artifacts/screenshots/`, используя отдельный профиль. Проверка анатомии атласов: `python tools/check_host_animation.py`.

Браузерная проверка: `node tests/browser-smoke.cjs`. Нужны Playwright и Chromium/Chrome. Скрипт сам запускает локальный HTTP-сервер, проверяет свежие desktop/touch-профили и сохраняет кадры `09_web_desktop.png`, `10_web_touch.png`. Для другого компьютера пути можно задать через `PLAYWRIGHT_MODULE` и `PLAYWRIGHT_CHROMIUM_EXECUTABLE`.

## Release-экспорт

В Godot должны быть установлены шаблоны экспорта той же версии. Готовые пресеты: `Windows Desktop` и `Web`.

```powershell
$godot = powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\tools\launch.ps1 -Mode FindGodot
New-Item -ItemType Directory -Path build, build/web -Force | Out-Null
& $godot --headless --path . --export-release 'Windows Desktop' build/Symbiont.exe
& $godot --headless --path . --export-release 'Web' build/web/index.html
```

Windows-пресет создаёт x86_64 EXE со встроенным PCK. Web-пресет использует Compatibility, отключает потоки и GDExtension, не включает PWA и добавление заголовков cross-origin isolation. Официальные параметры описаны в документации [Windows](https://docs.godotengine.org/en/stable/classes/class_editorexportplatformwindows.html) и [Web](https://docs.godotengine.org/en/stable/classes/class_editorexportplatformweb.html).

Документация, референсы, исходные арты, инструменты, тесты и скриншоты остаются в исходном проекте и исключаются из игровых пакетов через `exclude_filter`.
